# ZTab API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A NestJS service in `api/` that stores encrypted tab blobs in PostgreSQL, proxies the watcher, returns each link only its role's slice, and pauses tabs nobody uses; plus the two small additions it needs in `watcher/` and `@ztab/crypto`.

**Architecture:** NestJS modules (`config`, `prisma`, `watcher`, `auth`, `tabs`, `sweep`, `status`, `lifecycle`) over Prisma 7 with the pg driver adapter. The watcher is reached over HTTP with a 5 s timeout and a 5 s in-process cache, no background polling. Access is a Bearer token derived in the browser by HKDF and stored only as a SHA-256 hash.

**Tech Stack:** Node 24, TypeScript 5.9, NestJS 12, Prisma 7 + `@prisma/adapter-pg`, PostgreSQL 16, zod 4, `@nestjs/throttler`, `@nestjs/schedule`, `helmet`, Jest 30 + supertest; Rust (watcher, axum + rusqlite); `@ztab/crypto` (Vitest).

**Spec:** `docs/superpowers/specs/2026-10-17-ztab-api-design.md` (spec). It references the watcher contract (`docs/superpowers/specs/2026-10-15-ztab-watcher-design.md` §6) and the key model (`docs/superpowers/specs/2026-10-16-ztab-crypto-design.md` §4).

## Global Constraints

- JSON `snake_case`; amounts in zatoshi as integers; time RFC 3339 UTC.
- Error body `{ "error": { "code", "message" } }`, codes exactly: `validation`, `not_found`, `unauthorized`, `forbidden`, `conflict`, `rate_limited`, `watcher_unavailable`, `watcher_rejected`. Watcher `4xx` → same status, `watcher_rejected`, watcher's message verbatim plus `watcher_status`; watcher `5xx`/`502`/timeout → `503 watcher_unavailable`; watcher `409` on registration → `409 conflict`.
- Token: `HKDF-SHA256(secret, salt = tab_id UTF-8, info = "ztab/v1/token")`, 32 bytes; header `Authorization: Bearer <base64url(token)>`; stored as SHA-256 (32 bytes); compared with `crypto.timingSafeEqual`.
- Missing token → `401`; unknown tab or a token that is not this tab's → `404` with an identical body; right tab, wrong role → `403`.
- `participants_count` 1..=20; body ≤ 64 KB; each blob ≤ 16 KB; `PUT /tabs` 10 per hour per IP; every other route 120 per minute per IP; IP from `X-Forwarded-For` (trust proxy = 1 hop).
- Watcher timeout 5 s, no retry; watcher `GET /v1/tabs/{id}` cache 5 s, invalidated by `sweep`/`broadcast`; `GET /status` cached 5 s.
- `last_access_at` updated at most once a minute per tab; archive after 7 days without access; delete 30 days after `closed_at`; archive cron hourly, delete cron daily.
- Logs carry only method, path, status, duration, error code. Never bodies, `Authorization`, blobs, addresses, amounts, txids, UFVKs, hashes.
- Env: `DATABASE_URL`, `WATCHER_URL`, `WATCHER_TOKEN`, `ZTAB_NETWORK` (`test`|`main`), `CORS_ORIGIN`, `PORT`; start fails without `DATABASE_URL` or `WATCHER_TOKEN`.
- Shell: prepend `$HOME/.nvm/versions/node/v24.18.0/bin:$HOME/Library/pnpm` to `PATH` for `pnpm`/`node`. Docker Desktop provides PostgreSQL for tests.
- Code and comments in English; commits `api: …`, `watcher: …`, `crypto: …`.

## Review Focus

1. A participant token used on another tab's id must give exactly the same `404` body as an unknown tab (Task 4 test `foreign token on another tab is indistinguishable from unknown tab`).
2. `PUT` retried after a network drop with the same `ufvk` and admin hash must succeed and not duplicate rows, even if the watcher already registered the tab (Task 6 test `retry after watcher success is idempotent`).
3. Watcher down during `GET` must still return the blob, addresses and `last_known_state` with `stale: true`, never a 500 (Task 7 test `watcher down returns stale snapshot`).
4. A request carrying `X-Forwarded-For` with several hops must rate-limit by the client IP the proxy appended, not by the proxy (Task 9 test `rate limit keys on forwarded client ip`).
5. A paused tab whose revival call to the watcher fails must still answer with `stale: true` and stay `paused` so the next request retries (Task 7 test `revival failure keeps tab paused`).
