# ZTab PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The React PWA in `pwa/` through which Alice creates a tab and shares links, a participant pays and sees a status, and Alice withdraws collected funds; plus the small watcher and API additions the spec's §13 requires (balance, sweep history, closed tabs keep watching, purge by inactivity, `GET /rate`).

**Architecture:** Vite + React single-page app; all crypto through `@ztab/crypto` in the tab; all data through the API. Pure domain modules (money, statuses, ZIP-321, withdraw gating) are plain TypeScript tested in Node; a thin service layer (keys, blobs, create, withdraw) wraps crypto + API and is tested with real crypto and a mocked `fetch`; pages compose them. Secrets live in memory only, the URL fragment is read once and removed.

**Tech Stack:** React 19.3, Vite 8.3 (the spec names Vite 7; 8.3.4 is current and the plugins below target it), TypeScript 5.9, Tailwind CSS 4.3 (`@tailwindcss/vite`), react-router 8.4, `qrcode` 1.5, `vite-plugin-pwa` 2.0, `@vitejs/plugin-basic-ssl` 2.3 (dev only), Vitest + Testing Library + jsdom, Playwright 1.64; Rust (watcher, axum/rusqlite); NestJS 12 (API).

**Spec:** `docs/superpowers/specs/2026-10-18-ztab-pwa-design.md` (spec; §13 lists the watcher/API additions). Contracts: API spec `docs/superpowers/specs/2026-10-17-ztab-api-design.md` §4/§6 and `api/README.md`; crypto exports `crypto/src/index.ts`; status rules spec §7 as amended by §13.4.

## Global Constraints

- English UI only. Button copy from the spec verbatim: **Create a tab**, **Create tab**, **Split equally**, **Copy**, **Share**, **Continue**, **Open admin page**, **Pay with your wallet**, **Other ways to pay**, **Copy address**, **Copy amount**, **Share link**, **Withdraw to my wallet**, **Confirm**, **Refresh**, **Retry**. Status badges: `Status unknown`, `Waiting for payment`, `Payment seen, confirming…`, `Paid`, `Paid · from a transparent address`, `Partially paid`, `Paid · overpaid`. Overpaid sentence: `Paid · $2.00 over, thank you`; underpaid: `Paid $8.00 of $12.50 · $4.50 left`. Error copy from spec §5.6 verbatim: `This tab does not exist or the link is wrong.`, `Live data is delayed; showing the last known status.`, `The network service is unavailable, try again in a minute.`, `Open this page over HTTPS`, `Loading crypto module…` / `Reload the page`, `Too many requests from your network, wait a minute.`, `This link is incomplete`, `Address mismatch, do not pay`, `The server returned addresses that do not match this tab`, `Save this link now. It is the only key to the money. We cannot recover it.`, `The server proposed a different payment. Nothing was signed.` Footer: `Payments are shielded. Only you and the organizer see this page.` (group mode: second sentence `Everyone with the group link sees this status.`). The word "close" never appears in the UI.
- Privacy (spec §9): no third-party domains at runtime (no CDN fonts/scripts, QR generated locally, rate via our API); fragment removed from the address bar after reading (`history.replaceState`); nothing about tabs in `localStorage`/`sessionStorage`/IndexedDB except the flag `ztab.adminWarningSeen`; `document.title` is always `ZTab`; service worker never caches API responses or `/t/*` pages; no `console.*` in production builds (`esbuild.drop: ['console','debugger']`); secrets (`master`, `spendSeed`, `orchardSk`, `rngSeed`, tokens) are `Uint8Array`s zeroed with `fill(0)` right after use (`master` stays in memory on the admin page); external links use `rel="noopener noreferrer"`.
- Amounts: cents and zatoshi as integers; `share_zat = Math.round(share_cents / 100 / rate * 1e8)`; ZEC shown with up to 8 decimals, trailing zeros trimmed (builder's call applied); USD with 2 decimals; fiat for payments uses the blob's fixed rate.
- API calls: every request except the first `PUT /tabs/{id}` carries `Authorization: Bearer <encodeToken(token)>`; a retried `PUT` carries the admin token; poll `GET /tabs/{id}` every 10 s, 5 s for 10 min after Pay; `birthday = tip_height − 20` from `GET /status`; `status_facts: null` renders `Status unknown`, never `Waiting`.
- Withdraw: the confirmation screen is built only from `inspectPczt`; the button is disabled when the server `summary` disagrees with the PCZT or the recipient differs from the blob's `withdraw_address`; signing via `signPczt(network, pczt, orchardSk, rngSeed, { recipient, totalZat, feeZat })` with a fresh `crypto.getRandomValues(new Uint8Array(32))`.
- Build config: `VITE_API_URL`, `VITE_NETWORK` (`test`|`main`), `VITE_EXPLORER_TX_URL` (template with `{txid}`), `VITE_DEMO_PAYMENT` (unset; reserved, unused). Mobile-first, single column ≤ 480 px, 16 px gutters.
- Shell: prepend `$HOME/.nvm/versions/node/v24.18.0/bin:$HOME/Library/pnpm` to `PATH`. Docker Desktop provides Postgres for API e2e (`pnpm --filter @ztab/api db:up`, port 55432). Code/comments in English; commits `pwa: …`, `watcher: …`, `api: …`.
- Rust and NestJS tasks follow the existing conventions of `watcher/` (axum, `WatcherError`, offline fixture harness `watcher/tests/common`) and `api/` (native ESM, `.js` import suffixes, zod `.strict()`, `ApiError`, stub watcher `api/test/stub-watcher.ts`).

## Review Focus

1. A participant top-up with 1 confirmation after an earlier payment with 3+ must not flip the badge to `Paid` early (Task 4 `status: top-up with 1 confirmation stays Partially paid`).
2. Opening a `/t/<id>#p=…` link, then pressing the browser Back/Forward or reloading, must still work (the fragment was removed): the page keeps the key in memory for the session and shows "This link is incomplete" only when the key was never there (Task 6 `reload after fragment removal keeps the key in memory`).
3. A watcher that proposes a sweep to a different address than the blob's must leave Confirm disabled and sign nothing (Task 9 component test + Task 10 e2e `tampered summary blocks confirm`).
4. The create form must reject a total that does not equal the sum of shares by exactly one cent and accept exact equality (Task 7 `one-cent mismatch disables Create`).
5. `GET /rate` failing must not block creation: the rate field becomes editable and the tab is created with the manual rate (Task 7 `manual rate when /rate is 503`).
