## Проблема

Коли компанія ділить рахунок, а хтось хоче отримати свою частину в ZEC, усе робиться вручну: попросити адресу, перерахувати долари в ZEC, перепитати, хто вже відправив. Це запит номер один у спільнотному wishlist на форумі Zcash. Його автор, core-розробник, описує саме цей біль після кожного Zcash-саміту.

Звичайні застосунки для поділу витрат роблять ситуацію гіршою з погляду приватності. У Venmo перекази між друзями за замовчуванням видно у стрічці, а в on-chain стейблкоїнах історія вічна і відкрита будь-кому.

## Як це працює

1. **Аліса створює таб.** Вводить суму в доларах, учасників і спосіб поділу. Браузер генерує для табу ефемерний ключ, курс ZEC фіксується на обмежений час.
2. **Кожен учасник отримує своє посилання.** Окрема shielded-адреса табу під кожну людину, сума в ZEC уже порахована, платіжний запит у форматі ZIP-321.
3. **Учасник платить зі свого гаманця.** На телефоні посилання відкриває гаманець із заповненими полями, на комп'ютері працює QR. Встановлювати нічого не треба.
4. **Сторінка табу оновлюється сама.** Статус кожного учасника змінюється з «очікує» на «в мемпулі» і «оплачено» після підтверджень.
5. **Таб закривається, кошти переходять Алісі.** Сервер готує переказ на її справжню адресу, браузер Аліси лише підписує його.

Застосунок ніколи не будує транзакцій учасників. Їх будують і підписують гаманці учасників, а ZTab рахує частки, видає платіжні запити, бачить вхідні платежі табу і допомагає Алісі забрати кошти.

## Сценарії

### Головні для демо

- **Вечеря або бар.** Шестеро друзів, один платить, решта розраховуються за хвилину.
- **Спільна оренда.** Щомісячний таб на оренду, комуналку й інтернет із сусідами. Це відповідь на критерій «чи скористаються цим у понеділок».
- **Витрати команди на івенті.** Житло, таксі й вечері на конференції. З блокчейну не видно, хто з ким працює і скільки витратила команда.

### Також підходить

Спільні підписки на сімейних планах, групові подарунки, подорожі з друзями, збори в DAO і ком'юніті, компенсація витрат у малій команді.

## Архітектура

Основа — офіційний Rust-стек Zcash (librustzcash), а не сторонні обгортки. Для мобільних гаманців є нативні SDK, але ZTab їх не потребує: це веб-застосунок, а транзакції учасників будують їхні гаманці.

```
 Браузер Аліси (PWA)          Браузер учасника
 ─ ефемерний ключ табу        ─ бачить свою частку
 ─ шифрує дані табу           ─ відкриває zcash: / QR
 ─ підписує PCZT                     │
        │  ciphertext, UFVK          ▼
        ▼                       Гаманець учасника ──► мережа Zcash
 API + relay (NestJS)                                     │
 ─ зберігає лише ciphertext                               │
 ─ видає статуси                                          │
        │ HTTP                                            │
        ▼                                                 │
 Watcher (Rust)                                           │
 ─ view-only акаунт на кожен таб                          │
 ─ мемпул + блоки, PCZT create/prove                      │
        │ gRPC (lightwallet-protocol)                     │
        ▼                                                 │
 Zaino (індексер) ◄── Zebra (повна нода) ◄────────────────┘
  
```

| Компонент | Відповідальність | Технології |
| --- | --- | --- |
| Веб-застосунок (PWA) | Створення табу, генерація ефемерного ключа, шифрування даних табу ключем з URL, сторінка оплати, підпис PCZT. | TypeScript, React, WebCrypto, підпис через WebZjs або крейт `pczt` у WASM |
| API і relay | Зберігає зашифровані блоби табів і UFVK активних табів, роздає оновлення статусів, викликає watcher. | NestJS, PostgreSQL, Redis |
| Watcher | Імпортує UFVK табу як view-only акаунт з birthday на момент створення, сканує лише свіжі блоки, розшифровує мемпул, рахує підтвердження, будує і доводить PCZT для закриття табу. | Rust: `zcash_client_backend` 0.24, `zcash_client_sqlite`, фіча `tor` для mainnet |
| Індексер | Віддає компактні блоки, транзакції і потік мемпулу. Власний, щоб метадані не потрапляли третій стороні. | Zaino поверх Zebra; на старті розробки публічний `testnet.zec.rocks` |
| Курс | Курс ZEC/USD без жодних даних користувача. | Публічний API ціни |

### Чому birthday важливий

Кожен таб — новий view-only акаунт із birthday на висоті створення. Watcher сканує лише блоки від цього моменту, тобто десятки чи сотні, а не всю історію ланцюга. Синхронізація табу має бути майже миттєвою, і це перше, що треба заміряти.

### Інструменти для перевірок і розробки

- **zcash-devtool** — для gate-перевірок без власного коду: `init-fvk` (view-only гаманець з UFVK і birthday), `sync`, повний PCZT-флоу (create, prove, sign, combine, send).
- **zingo-cli** (zingolib) — запасний інструмент, якщо щось не піде з devtool.
- **Zodl wallet threat model** — шаблон для нашої threat model.

## Ключі та PCZT

Головне архітектурне рішення: сервер ніколи не має права витрачати кошти і не бачить нічого за межами одного табу. Для цього кожен таб отримує власний ефемерний ключ, а закриття табу розділене через PCZT (частково зібрані транзакції) на важку частину на сервері і легку в браузері.

1. **Створення.** Браузер Аліси генерує ефемерний seed табу. Spending key живе лише у фрагменті її адмін-посилання (після #), на сервер іде тільки UFVK табу.
2. **Збір.** Учасники платять на diversified-адреси ефемерного ключа. Watcher бачить лише платежі цього табу.
3. **Закриття.** Watcher будує PCZT для переказу всієї суми на справжню адресу Аліси і робить доведення (важка частина).
4. **Підпис.** Браузер Аліси підписує PCZT ключем з фрагмента URL. Це дешево і не вимагає доведень у WASM.
5. **Відправка.** Підписаний і доведений PCZT об'єднуються, транзакція йде в мережу.

**Ризик втрати коштів.** Якщо Аліса загубить адмін-посилання до закриття табу, кошти залишаться на ефемерному ключі. Пом'якшення: автоматична пропозиція закрити таб, щойно всі заплатили; явний експорт резервної копії ключа; попередження при створенні табу.

Запасний варіант, якщо підпис PCZT у браузері не складеться: Аліса створює окремий акаунт у своєму гаманці і дає ZTab лише його UFVK. Тоді кошти одразу у неї, але це залежить від підтримки кількох акаунтів у гаманцях.

## Статуси оплат

| Статус | Умова | Що означає для користувача |
| --- | --- | --- |
| Очікує | Платежу на адресу учасника немає | Учасник ще не платив |
| В мемпулі | Транзакцію розшифровано в мемпулі | Лише інформаційний сигнал, не підтвердження |
| Оплачено | Транзакція в блоці і має N підтверджень | Частку зараховано |
| Оплачено з прозорої адреси | Підтверджено, але вхід був transparent | Гроші дійшли, але відправник видимий у блокчейні |
| Недоплата або переплата | Сума відрізняється від частки | Показується різниця, Аліса вирішує, що робити |

Статус «оплачено» ніколи не ставиться за самим лише мемпулом. Зламаний або нечесний індексер може показати транзакцію, якої немає, тому підтвердження в блоках і власний індексер обов'язкові. Watcher також обробляє реорги: якщо транзакція зникла з ланцюга, статус повертається назад.

## Threat model

Формат взято з wallet threat model від Zodl (Invariant-Centric Threat Modeling): ми перелічуємо, що гарантуємо проти кожного рівня противника, і чесно називаємо відомі слабкі місця. На жодні властивості поза цим списком покладатися не можна. Противники впорядковані від найслабшого до найсильнішого, кожен сильніший має всі можливості слабших.

| Противник | Гарантуємо, що він не може | Відомі слабкі місця |
| --- | --- | --- |
| Знає адреси, бачить блокчейн | Дізнатися учасників, суми, зв'язок платежів між собою і з табом | Бачить платежі з transparent-адрес (ми їх виявляємо і позначаємо) |
| Бачить мережевий трафік | Прочитати вміст табів: імена, частки, статуси зашифровано | Бачить, що людина користується ZTab і коли; на mainnet IP-адреса watcher прихована через Tor |
| Оператор стороннього індексера | Не застосовується, якщо використовується власний індексер (тестнет-демо) | З публічним індексером: може зіставити відправки учасників з отриманнями ZTab і показати фальшиві підтвердження |
| Зламаний сервер ZTab | Витратити кошти, прочитати імена і вміст табів, побачити гаманці учасників і Аліси поза табом | Бачить суми платежів активних табів; може віддати модифікований JavaScript, який викраде ключ з URL |

### Пом'якшення відомих слабких місць

- **Модифікований JavaScript:** відкритий код, Subresource Integrity, статичний фронтенд окремо від API.
- **Кореляція на індексері:** власні Zaino і Zebra; для mainnet це рекомендована конфігурація в README.
- **Фальшиві підтвердження:** лише блоки з N підтвердженнями, мемпул тільки як підказка.
- **Transparent-платежі:** детекція і позначка у статусі, список перевірених shielded-гаманців на сторінці оплати.

## Сумісність з гаманцями

ZTab працює з будь-яким Zcash-гаманцем, який підтримує shielded-відправку і ZIP-321, без жодної інтеграції з боку гаманця. Кандидати для перевірки: Zodl, Zingo!, Zkool, Vizor, Keystone, Edge, Cake Wallet, YWallet.

QR працює всюди. Відкриття посилання `zcash:` з мобільного браузера залежить від гаманця. Як гаманці обробляють такі посилання, видно в коду мобільних SDK, а результат ручної перевірки чесно вказується в README.

## Скоуп MVP

### Входить

- Створення табу з сумою у фіаті та фіксованим курсом, поділ порівну з ручним коригуванням.
- Ефемерний ключ табу, diversified-адреса і ZIP-321 запит для кожного учасника.
- Watcher з view-only акаунтом на таб, мемпулом і підтвердженнями.
- Закриття табу через PCZT з підписом у браузері.
- Шифрування даних табу ключем із фрагмента URL.
- Повторювані таби для оренди й підписок.
- Тестнет-демо на власних Zebra і Zaino.

### Свідомо не входить

- Крос-чейн оплата з USDC, SOL чи ETH. Доставка зі свопу через NEAR Intents на shielded-адресу поки неможлива, а прозорий хоп був би витоком.
- Поділ по позиціях чека і розпізнавання фото чека.
- Власний гаманець і нативний мобільний застосунок.
- Мінімізація боргів між кількома платниками.
- Власний mainnet-індексер: описується в README як рекомендована конфігурація.

## Ризики та відкриті питання

- **Підпис PCZT у браузері може не скластися.** Запасний варіант: окремий акаунт у гаманці Аліси і лише його UFVK для ZTab.
- **Синк Zebra на тестнеті може зайняти довше, ніж є часу.** До переходу на власний індексер використовується публічний тестнет-сервер, а перехід робиться наприкінці.
- **Rust — новий стек.** Watcher навмисно вузький, а devtool і zingolib дають готовий референсний код.
- **Втрата адмін-посилання.** Кошти лишаються на ефемерному ключі; потрібні резервна копія і швидке закриття табу.
- **NU7 посеред суддівства.** Перевірка сумісності заздалегідь, моніторинг деплою після 5 листопада.
- **Нішевий ринок.** Реалістичний шлях після хакатону — грант Zcash Community Grants.
- **Splitz.** Позиціонування має бути в описі з першого рядка.

## Чернетка опису для форми

Поле Description обмежене 2000 символами і просить пояснити, що робить продукт, чому він не протікає, і що в ньому справжнє, а що мок. Перед подачею блок «Real vs mock» треба заповнити за фактичним станом.

```
ZTab splits a shared bill and settles it in shielded ZEC. The payer creates a tab in USD; each participant gets a link with their share in ZEC at a locked rate and pays from any Zcash wallet that supports shielded sends and ZIP-321. No install, no wallet integration. Built on librustzcash.

Why it does not leak:
- Chain: shielded-only, one diversified address per participant.
- Keys: each tab has an ephemeral key generated in the payer's browser. The server only gets that tab's viewing key, never a spending key, and nothing outside the tab. Closing a tab uses PCZT: the server builds and proves the sweep, the browser signs it.
- Content: names, shares and statuses are encrypted with a key in the URL fragment, which never reaches the server.
- Infrastructure: the demo runs on our own Zebra + Zaino, so no third-party indexer sees our queries. "Paid" requires block confirmations, never mempool alone.
- Routes: no swaps, no transparent hops. Transparent-source payments are detected and flagged.
Full threat model by adversary tier in the README, including known weaknesses (e.g. a compromised server could serve modified JS).

Why not Splitz: Splitz is a protocol for wallets to integrate. ZTab works today with wallets that integrated nothing.
```
